# Issue #51：文本型 PDF / Word 的替换回写与导出（保留格式）

- 总述：#6　核心引擎：#7

## 1. 概述

将替换结果**回写到文档并导出**，保持原文档版式。本期范围：**文本型 PDF 和 Word（.docx）**；扫描型 PDF 因需版面重建暂不在本期（后续跟进）。

## 2. 文本型 PDF

替换词与原词长度通常不同，直接改写文本对象会导致偏移。建议策略（按优先级）：

1. **同长度替换**：优先从词池中挑选长度一致（或可接受缩放）的替换词；
2. **文本对象级重写**：修改 PDF 内容流中的 `Tj/TJ` 文本并重排该行（依赖 pymupdf 等库的 redaction/insert 能力）；
3. **兜底**：对替换区域做同底色矩形覆盖后写入新文本。

需处理 **CID 字体子集缺字**问题：替换词用到的字形可能不在子集内，需嵌入补充字体或改用标准字体绘制替换词。

## 3. Word（.docx）

- 基于 python-docx / OOXML 直接修改 run 文本，天然支持长度不同的替换；
- 保留样式、表格，页眉页脚中的实体也要替换；
- 追踪修订/批注中的敏感实体同样需要处理或清除。

## 4. 交付物

- 文本型 PDF 替换导出管线 + Word 替换导出管线；
- 导出前后对比自检（替换词全部落盘、无遗漏实体、文件可正常打开）。

## 5. 验收标准

- 样本文档替换导出后：版式无肉眼可见破坏、全部映射实体已替换、残留实体扫描为 0；
- 导出文件可被主流阅读器 / Office 正常打开。
