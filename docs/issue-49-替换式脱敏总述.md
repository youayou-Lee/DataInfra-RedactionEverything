# Issue #49：替换式脱敏总述（同类型虚构词替换，可自定义词池）

- 日期：2026-09-08　级别：P1（企业级必修）　状态：需求拆分中
- Issue：https://github.com/youayou-Lee/DataInfra-RedactionEverything/issues/6

## 1. 需求背景

目前系统的脱敏方式是「关键信息识别 + 打码」。在法律文书等场景下，打码会破坏文档的可读性和篇幅结构，往往希望**保留文档整体形态，仅将敏感实体替换为同类型的虚构词**，例如：

- 人名 → 张三、李四、王五（可由用户指定替换词池）
- 公司/机构名 → 某公司、某人民法院
- 地址 → 某市某区某街道
- 身份证号、电话 → 符合格式的虚构号码

## 2. 总体思路

替换式脱敏与打码式脱敏并存，用户在任务/文档级别选择模式。关键点：

1. **同一实体全局一致**：同一个「陈明飞」在全文所有位置应始终替换为同一个「张三」，需要文档级实体映射表（entity → pseudonym）；
2. **替换词池可配置**：用户可指定每类实体使用的替换词池（或自定义映射），词池耗尽时可循环或自动生成（如「张三1」）；
3. **类型感知**：替换词需与实体类型匹配（人名换人名、地名换地名），并保证替换后文本语法通顺；
4. **范围**：扫描型 PDF 的版面回写难度大，本期先支持**文本型 PDF 和 Word（docx）**；扫描件场景后续跟进（依赖版面重建能力）。
