# Issue #48：扫描型 PDF 被误判为文本型，导致脱敏信息漏识别

- 日期：2026-09-08　级别：**P0（交付阻塞/数据风险）**　状态：待修复
- Issue：https://github.com/youayou-Lee/DataInfra-RedactionEverything/issues/5
- 关联：#49～#52（替换式脱敏）、#47（海光适配）

## 1. 问题描述

通过前端上传文件进行识别时，扫描型 PDF 被当作文本型 PDF 处理，走文本提取链路后识别结果很差，该脱敏的信息（人名、身份证号、住址等）大量漏识别。

## 2. 根因分析

扫描型 PDF 在制作时往往内嵌一个由 OCR 生成的文本层。该文本层质量很差：

- 文字断行、乱序、缺字严重（如「7 月8 日收讫 / 2026 年 / ( 优 / 婷收」）；
- 表格类版面（卷宗封面）提取后字段错位严重；
- 文本层内容与图像实际内容不完全对应。

目前的文件类型判断逻辑可能仅凭「能否提取到文本 / 是否含字体对象」就判定为文本型，于是直接使用了这些低质量文本，没有触发视觉链路（OCR / PaddleOCR-VL / HaS-NER）。

## 3. 复现样本

内部环境中的真实文书（路径供内部参考，不入库）：

| 文件 | 页数 | 特征 |
|---|---|---|
| `/home/you/图片/执行异议书.pdf` | 6 | 扫描件带内嵌 OCR 文本层（STFangsong CID 字体），文本层断行乱序 |
| `/home/you/桌面/caseData/xbg/陈明飞诈骗案/[证据卷]2.pdf` | 86 | iText 5.3.2 生成，扫描件带内嵌文本层，表格版面字段错位严重 |

## 4. 修复方案

1. **增强文件类型判定**：对「有文本层但文本密度异常 / 断行严重 / 乱码率高」的 PDF 回退或并行走视觉链路；
2. **前端手动指定**：提供处理链路选择入口（文本型 / 扫描型）；
3. **置信度仲裁**：两条链路都可给出结果时，取实体置信度更高者。

## 5. 验收标准

- 两个复现样本分别按正确链路处理后，敏感实体（人名、身份证号、住址、统一社会信用代码）召回率与人工标注一致（目标 ≥ 95%）；
- 常规文本型 PDF / Word 不因新判定逻辑被误分流到视觉链路（回归测试集全绿）；
- 单元测试覆盖类型判定的边界样本（空文本层、纯图像、混合型）。
