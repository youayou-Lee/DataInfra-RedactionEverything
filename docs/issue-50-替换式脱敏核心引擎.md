## 1. 概述

实现与「打码」并列的**替换式脱敏核心引擎**：识别出敏感实体后不遮挡，而是替换为同类型的虚构词。

## 2. 核心设计

### 2.1 文档级实体映射表（Entity Mapping）

- 识别阶段产出的每个实体（文本、类型、位置、出现次数）先归一化合并（同一人名多种写法可由人工确认）；
- 每个唯一实体分配一个固定替换词，保证全文一致性；
- 映射表支持导出/导入，便于文档间保持同一套化名（同一案件中跨文书一致）。

### 2.2 替换词池管理

- 内置默认词池：人名（张三、李四、王五、赵六…）、公司名、地名、银行、法院等常见类型；
- 用户可自定义词池：按实体类型上传/编辑替换词列表，或直接指定「原词 → 替换词」映射；
- 词池耗尽时的策略：循环使用、加序号（张三1、张三2）、或基于规则自动生成（如符合身份证/手机号格式的虚构号）。

### 2.3 类型感知替换

- 替换词类型必须与实体类型一致；
- 可结合 LLM 做通顺性校验（替换后语句自然）。

## 3. 交付物

- 后端替换引擎模块（独立于现有打码流程，可按配置切换）；
- 单元测试覆盖：实体一致性、词池耗尽、类型匹配、边界情况（实体跨行/跨块）。
